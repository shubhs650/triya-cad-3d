- 2026-10-17 — Overlay architecture with whitelisted seams; merge-based sync; freeze until beta (ADR-0002).
- 2026-10-17 — Vessel module = command generator, not a FeatureKind (ADR-0003).
- 2026-10-17 — Drawings data-driven, native Rust, no OCCT (ADR-0004).
- 2026-10-18 — Vessel JSON persisted in `Document.metadata["in.openengtools.triya.vessel"]` (ADR-0005, confirmed in code).
- 2026-10-18 — Keep all upstream identifiers; rename display only (ADR-0006).
- 2026-10-18 — EIL tables never in the repo; private import (ADR-0007).
- 2026-10-18 — Command registration via a runtime extension slot (`engine/cmd/triya_extra.rs`) called by Triya app shells; static reference impossible (Cargo cycle).
- 2026-10-18 — Skeleton adds a `VESSEL` ribbon tab (seam + 3 locale lines); revisit at T5.1.
- 2026-10-18 — CI toolchain = current stable (1.99.1 on Actions, `dtolnay/rust-toolchain@stable`), not 1.95: `rust-version = "1.95"` is upstream's MSRV, and upstream v0.14.0's own `clippy -D warnings` fails on 1.95/1.96 (`geom/fill_general.rs:166` nonminimal_bool) and 1.97 (`kernel/prism_local.rs:242` manual_range_contains) but passes on 1.99.1. Local gate: `cargo +1.99.1 xtask ci`.
- 2026-10-18 — `triya-cli` compiles upstream's `apps/solidcraft-cli/src/main.rs` unmodified: its `build.rs` copies it to `OUT_DIR` renaming `fn main` → `fn upstream_main` and absolutising `mod`/`#[path]` lines (build fails if an anchor disappears); no seam beyond a `triya-cli` row in layers `TABLE` (row 10). Chosen over copying 2.5 k lines (drift) and over a `pub fn main` seam (owner decision).
- 2026-10-18 — Web service worker keeps upstream's `solidcraft-app` cache names: `xtask web-offline-test` hard-codes them; cache names are identifiers (ADR-0006) and the site path in the name separates Triya from SolidCraft.
- 2026-10-18 — Seam patches are generated by `triya/ci/refresh-seam-patches.sh` and checked in Triya CI (`--check`).
- 2026-10-18 — Desktop app is a thin wrapper around `SolveApp`, not a copy of upstream's 2,700-line app.

- 2026-10-18 — T2.1: the model follows `vessel-schema.md` field for field and replaces the skeleton's shapes (`id_or_od_mm` → optional `diameter_mm`, `name` → `title`, `kind` is a flat tag beside the fields, `axial {ref: datum|host_from, mm}`). - 2026-10-18 — Unknown fields are kept at the top level only (`#[serde(flatten)]` map, with `extra` ≤ 16 KiB together); inside elements/attachments the flattened `kind` tag rules out a second flatten, so unknown keys there are dropped. The round-trip test fails if a known field is dropped.

- 2026-10-18 — Caps set in T2.1 with the rewrite: 200 elements, 500 attachments (PLAN T2.6 tests them), counts 1…1000, text ≤ 4 KiB.
